## 阶段 2：SAPIEN human 窗口三连坑（run_demo.py）

调试期需要 human 窗口目检，在 Windows 上连续踩中三个 SAPIEN 查看器问题，最终都固化在 [run_demo.py](../run_demo.py) 的 `render_retry()`：

1. **首帧尺寸竞态**：窗口刚创建时 `window.size` 可能为 0，原生 render 抛 `failed to resize: width and height must be positive`。捕获后泵消息、`update_render()`、短暂等待再重试；
2. **最小化即"未响应"**：窗口最小化时尺寸为 (0,0)，SAPIEN 自身的事件泵**不再服务 Win32 消息队列**，窗口永久卡在未响应，SC_RESTORE/WM_CLOSE 都无法处理；而原生 render 在尺寸 0 时是**阻塞**（不是异常，try 不到）；
3. **解法**：渲染前查尺寸，为 0 期间用 ctypes 自己 `PeekMessageW/TranslateMessage/DispatchMessageW` 泵 Win32 消息 + `win.update_render()` + sleep 跳过本帧；关闭走 `window.should_close → viewer.close()`。已实测：最小化保持 Responding、可恢复、最小化状态下点 X 能干净退出（exit 0）。

教训：

- 曾尝试用跨进程 `ShowWindow` 强行最小化/恢复做测试，反而把 SAPIEN 卡死（Responding=False），**不要再用**；要模拟最小化/恢复请用 `PostMessage` 发 `SC_MINIMIZE(0xF020)` / `SC_RESTORE(0xF120)`；
- human 渲染必须 `env.unwrapped.render_human()`，`TimeLimitWrapper` 没有这个方法。

## 阶段 5：真实抓放攻坚（本项目最核心的一段）

### 5.1 mplib 不可用，换自研运动层

- 官方 `pip install mplib` 只有 Ubuntu wheel；GitHub nightly release 也只有 manylinux；PyPI 的 `mplib 0.2.1` 是同名无关旧包；源码编译需 OMPL/FCL，Windows 不可行——**三条路全堵死，放弃**；
- 研读 ManiSkill main 分支 `examples/motionplanning/`（panda/solutions/pick_cube.py、base_motionplanner、two_finger_gripper）：
  - 时序：张开 → screw 到 grasp 上方 0.05 → 到 grasp → 闭合 → 到 goal；
  - 动作 = `np.hstack([7 关节角, gripper_state])`，走 `pd_joint_pos`；
  - 夹爪归一化 **OPEN=+1 / CLOSED=-1**，开合各保持若干步；
  - grasp 姿态用 `agent.build_grasp_pose(approaching, closing, center)`；
- 写 [panda_motion.py](../panda_motion.py)：SAPIEN pinocchio wrapper 的 CLIK 逆解 + 6mm 笛卡尔直线 + 暖启动 + 关节增量细分；控制模式从 `pd_ee_delta_pose`（7 维）切到 **`pd_joint_pos`（8 维）**；`max_episode_steps` 200→400。

### 5.2 调试顺序与五个坑（按发现顺序）

**坑 1：`ImportError: cannot import name 'quatconj'`**

transforms3d 的四元数函数名是 **`qconjugate`（共轭）和 `qmult`（乘积）**，不存在 quatconj/quatmultiply；mat2quat/rotate_vector 名字正确。改 import 与全部调用点。

**坑 2：测试报"抓起成功"但物体根本没动（假成功）**

第一版 `pick_part(part_pose, half_h)` 的入参是调用时拍的 `actor.pose`——**ManiSkill 的 Pose 对象是快照**，序列执行完再从这个旧快照读 z，永远是初始值 0.04，刚好大于 0.10 的判定阈值……实际最初是反向暴露：返回 z 始终 0.04，显示未抓起。统一改为**传 actor，在动作序列的每个关键节点实时 `actor.pose.p[0]` 读位姿**。同期修了测试脚本里 info 键名大小写（`part_A_in_box`，不是 `part_a_in_box`）。

**坑 3：蓝圆柱从 reset 起就是"躺倒"的（最隐蔽的一个）**

- 现象：seed=7 零件 A 抓不起；零动作静置观察，圆柱中心稳定在 z=0.03 而不是 0.04；
- 排查：分段下降 + `agent.is_grasping()` + 截图 + 接触点检查，排除了 IK 翻腕（最大关节跳变仅 0.03rad，轨迹无问题）；
- 根因：**SAPIEN/PhysX 的圆柱碰撞/视觉几何体轴沿本地 +X**，identity 位姿下圆柱横躺在桌面（中心高=半径 0.03），顶抓姿态下降根本对不准；
- 解法：初始姿态绕 Y 轴 -90°（wxyz `[0.707, 0, -0.707, 0]`）把轴转到世界 +Z，reset 随机化时也用同一固定姿态（圆柱旋转对称无需随机朝向）。修完静置中心稳定 z=0.04。

**坑 4：安全高度 0.17 仍会擦碰零件**

圆柱直立后顶高 0.08，末段水平移动时夹爪/手部在 0.17 高度仍会擦碰物体。测量 URDF：`panda_hand_tcp` 在 hand 前方 0.1034，手指结构与 TCP 基本齐平但手腕/手掌轮廓更大。把 `SAFE_Z` 提到 **0.21**（指尖下方约 0.1m，越过 0.08 高的物体），放置上方高度同步到 0.23。

**坑 5：零件 B 在个别随机位姿抓不起——指尖撞盒墙**

- 现象：零件 B seed=7，下降到 z=0.06 后再也下不去（IK 目标可达，但实测关节差 0.05rad，PD 被物理顶住）；
- 用 `scene.get_contacts()` 列接触对，发现 `panda_rightfinger <-> box_wall3` 多点接触：张开的右指尖（TCP 侧向约 +0.05m）已经压在 y≈0.14 的盒墙上，同时方块被挤偏；
- 解法：零件 B 随机范围 y 从 (0.04, 0.12) **收窄到 (0.02, 0.08)**，给指尖-盒墙留 ≥1cm 裕量；
- 同类教训：**物体随机范围要按"机器人运动时的外廓"而不是"物体本身位置"来定边界**。

### 5.3 验证

- `test_pickparts.py --part both --seeds 3 7 11 21`：**8/8 全部抓起且入盒**（全成功 exit 0）；
- Agent 端到端 `agent_main.py -instruction "把零件A放进盒子里"`：DeepSeek 严格按 `pick(A) → place(box)` 两步执行（无多余调用），工具返回"零件A入盒=True"后才汇报成功，并主动说明零件B未受影响；human 窗口收尾循环稳定。

### 5.4 顺手修的 pd_joint_pos 漂移问题

切到绝对关节角控制后，run_demo 原来的"零动作 = 全零向量"会让机械臂朝零位漂走，随机动作 `action_space.sample()*0.1` 也变成了"指向 0 附近的绝对目标"。改为：hold 动作 = 当前 get_qpos()[:7] + 夹爪 1.0；随机扰动 = 当前角 ±0.02rad 并 clip 到关节限位；run_demo 新增按键 1/2 直接演示抓放 A/B。

## 给后续维护者的方法论备注

- **物理类问题不要只看规划输出**：IK 成功 ≠ 物理到位。本项目 5 个抓放坑里 3 个（圆柱躺倒、撞墙、安全高度）规划轨迹都"正确"。有效手段固定为：分段 move_to + 读 `is_grasping`/实时位姿 + `scene.get_contacts()` 接触对（SAPIEN 接触点 API 是 `contact.bodies[0/1].entity.name`、`point.position`）+ 离屏截图；
- 调运动参数开 `PANDA_DEBUG=1`，看每段最大关节跳变（翻腕/奇异点）和执行中 TCP 实际最低 z（被物理顶住或路径下凹）；
- 改场景几何后必须重跑 `test_pickparts.py` 多种子回归，单种子通过不算数（坑 5 只在特定随机位姿出现）；
- 任何对 Qwen-Agent/安装包的修复优先用运行时 monkeypatch，并在代码注释写明"为什么、对应哪个版本"，升级框架时才知道能否移除；
- 后续接视觉感知时，替换点明确：sim_skills 里读取真值 actor.pose 的位置，换成 RGB-D 分割解算的物体世界坐标；技能语义和运动层都不用动。
