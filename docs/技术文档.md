# 技术文档：PickParts 具身智能 Demo

> 一句话定位：在 ManiSkill3 仿真器中，用云端 LLM（DeepSeek）作为"大脑"、自研运动规划层作为"小脑"，驱动桌面固定 Panda 单臂，按自然语言指令把零件 A（蓝圆柱）/零件 B（黄方块）抓进盒子。
>
- 运行环境：Windows + Python 3.10 + **纯 CPU**（torch CPU 版，渲染也走 CPU）
- 最近一次验证：离屏回归 4/4 入盒、扩展回归 8/8 入盒、Agent 端到端单指令成功

## 2. 仿真场景设计

### 2.1 在哪里设计

全部在 [pick_parts_env.py](../pick_parts_env.py)：

- `@register_env("PickParts-v1", max_episode_steps=400)` 注册环境名（episode 步数从默认 200 提到 400，因为真实运动序列比随机策略长）；
- `PickPartsEnv(BaseEnv)`：继承 ManiSkill 的 `BaseEnv`，机器人固定为 Panda（`SUPPORTED_ROBOTS = ["panda"]`，构造默认 `robot_uids="panda"`）；
- 稀疏奖励 `reward_mode="sparse"`（本项目 Agent 不看奖励，只用 `evaluate()` 的成功标志）。

### 2.2 场景组件清单

| 组件 | 来源 | 关键设计 |
|---|---|---|
| 桌面 + 地面 + 光照 | ManiSkill `TableSceneBuilder` | 一行 `build()` 获得标准桌面；`initialize()` 时自动把 Panda 基座放到近侧桌边 `(-0.615, 0, 0)` 并设置初始关节姿态 |
| Panda 单臂 | ManiSkill 内置 `Panda` agent | panda_v2.urdf，7 臂关节 + 二指 mimic 夹爪；TCP link = `panda_hand_tcp`（代码里用 `agent.tcp`） |
| 零件 A：蓝圆柱 | `actors.build_cylinder` | 半径 0.03、半高 0.04；动态刚体；**摆位时绕 Y 轴 -90°**（见 2.5） |
| 零件 B：黄方块 | `actors.build_cube` | 半边长 0.025；动态刚体；绕竖直轴随机朝向 |
| 盒子：1 底板 + 4 墙 | 原生 `scene.create_actor_builder()` 拼 5 个 box | 全部 **kinematic**（不受力移动），保证判定基准稳定；中心 `(0, 0.25)`，内腔半宽 0.055，壁厚 0.006，墙高 0.03，底板上表面 z=0.006 |
| 俯视相机 | `CameraConfig("base_camera", 128×128)` | 桌面斜上方固定视角，给将来的视觉感知预留（当前 Agent 尚未使用图像） |
| 观察相机 | `CameraConfig("render_camera", 512×512)` | human 窗口的好看视角 |

### 2.3 坐标系与布局

ManiSkill 桌面系：**桌面 z=0，x 指向桌子深处（机械臂正前方），y 向左为正**。

```
                    桌子深处 (x+)
         盒子 (0, 0.25)
                          零件B：x∈(-0.05,0.10), y∈(0.02,0.08)
   y-                                    y+
                          零件A：x∈(-0.05,0.10), y∈(-0.18,-0.05)
                    Panda 基座 (-0.615, 0)
                    桌子近侧 (x-)
```

- 零件 A/B 在左右两个分区，颜色 + 形状双重区分，避免互相干扰且为将来的视觉识别留足特征；
- 零件和盒子全部落在 Panda 工作空间内（经 IK 实测可达）；
- 零件 B 的 y 上限刻意压到 0.08：夹爪张开后指尖外沿到 TCP 侧向约 0.05 m，而盒墙近边在 y≈0.14——再远下降时指尖会撞墙推飞方块（实测踩坑，见执行记录）。

### 2.4 随机化与成功判定

`_initialize_episode()`：每次 reset 只随机两个零件的 x/y 位置；零件 B 另加竖直轴随机朝向；零件 A 圆柱旋转对称、固定姿态。

`evaluate()` 返回：

- `part_A_in_box` / `part_B_in_box`：零件中心在盒子开口范围内（xy 距中心 < 0.055）且高度 0 < z < 0.08；
- `success`：任一零件入盒。

`_get_obs_extra()` 把 TCP 位姿和两个入盒标志塞进观测，同时技能层也直接调 `evaluate()` 把成功标志作为文本回传给 LLM。

### 2.5 两个必须知道的场景细节

1. **SAPIEN 圆柱几何体的轴沿本地 +X**（PhysX 约定，不是 Z）。直接用 identity 位姿放圆柱，它在桌面上是"躺倒"的（中心高度只剩半径 0.03）。直立摆放必须给初始姿态绕 Y 轴 -90°，四元数（wxyz）`[0.707, 0, -0.707, 0]`。
2. **盒子用 kinematic 而非动态刚体**：任务语义里盒子是固定容器；若做成动态的，机械臂擦碰会让盒子位移，成功判定基准随之漂移，仿真也更不稳定。

### 2.6 控制接口（8 维动作）

环境以 `control_mode="pd_joint_pos"` 创建，每步动作是一个 8 维向量（控制器配置见 ManiSkill 内置 `agents/robots/panda/panda.py`）：

- 前 7 维：7 个臂关节的**绝对目标角（弧度）**，`PDJointPosController`（`normalize_action=False`，直接吃弧度）；
- 第 8 维：归一化夹爪指令，`PDJointPosMimicController` 联动两根手指——`+1` 张开到 0.04 m，`-1` 闭合（映射下限 -0.01，是保持薄物体夹持力的 trick）。

> 注意：因为是绝对角控制，"保持不动"的动作不是全零，而是"当前 7 关节角 + 夹爪当前状态"，否则机械臂会朝零位漂。run_demo.py 的 `hold_action()` 和 agent_main.py 收尾循环都按此处理。

## 3. 动作 / 技能设计

分三层，从机械到语义：

### 3.1 第一层：运动原子（panda_motion.py 的 `PandaMotion`）

构造时从已加载的 articulation 导出 pinocchio 模型（`robot.create_pinocchio_model()`），运动学与仿真零偏差；并固定一个"自上而下顶抓"姿态 `R=[ortho, closing, approaching]`，与官方示例 `agent.build_grasp_pose` 同约定。

| 方法 | 做什么 |
|---|---|
| `_ik(世界点, 暖启动q)` | 世界坐标→base 坐标（`_world_to_base`，处理基座偏移）→ pinocchio 阻尼最小二乘 CLIK（300 次迭代），只激活前 7 轴；失败抛 `MotionPlanError` |
| `move_to(x,y,z)` | 起止点切 6 mm 笛卡尔直线 → 逐点 IK 且**以上一点的解暖启动**（保证关节解连续、不翻腕）→ 相邻解按每步最大 0.06 rad 细分 → 逐帧 `env.step` → 末端再保持 3 步等 PD 收敛；返回末端定位误差 |
| `set_gripper(open)` | 切夹爪指令并保持 8 步等手指到位 |
| `pick_part(actor, half_h)` | 张开 → 到零件正上方 z=0.21 → 竖直下降到物体中心 z=half_h → 闭合 → 抬回 z=0.21；**入参传 actor 实时读位姿**（ManiSkill 的 pose 对象是快照，不能传缓存的 pose） |
| `place(x,y,target)` | 盒子上方 z=0.23 → 下降到 `底板0.006 + 物体半高 + 0.01` → 张开 → 竖直撤离 |

关键常量（都在文件顶部，调参只改这里）：

| 常量 | 值 | 含义 |
|---|---|---|
| `STEP_M` | 0.006 m | 笛卡尔路径点间距（约 0.12 m/s） |
| `MAX_DQ` | 0.06 rad | 单步最大关节增量 |
| `SAFE_Z` | 0.21 m | 水平平移高度：指尖在 TCP 下方约 0.1 m，必须越过最高零件顶（0.08 m） |
| `SETTLE_STEPS / GRIP_STEPS` | 3 / 8 | 到位保持 / 夹爪保持步数 |
| `BOX_FLOOR_TOP_Z` | 0.006 | 盒底上表面 |

桌面抓放不需要 RRT 避障规划：所有水平移动统一在安全高度进行，只有正上方/目标正上方才竖直升降，路径天然无碰撞。

设环境变量 `PANDA_DEBUG=1` 运行时，每个 `move_to` 会打印 IK 关节跳变和执行中 TCP 实际最低高度，便于排查"轨迹上没问题但物理上被撞"类问题。

### 3.2 第二层：LLM 工具（sim_skills.py）

Qwen-Agent 的 `BaseTool` 三要素：`name`、给 LLM 看的自然语言 `description`（含坐标系、取值范围、注意事项）、JSON Schema `parameters`，加真正执行的 `call()`。

| 工具 | 入参 | 执行 | 返回给 LLM 的文本 |
|---|---|---|---|
| `move_to` | x, y, z | `PandaMotion.move_to` | 完成位置 + 末端误差 + 夹爪坐标 + 两个入盒标志 |
| `pick` | part ∈ {A, B} | 取 actor/半高 → `pick_part` | "成功抓起/未能抓起" + 物体实时高度 + 入盒标志 |
| `place` | target ∈ {box, table} | box 用固定盒心坐标，table 用当前 TCP 的 xy → `place` | 放置完成 + 入盒标志 |

设计要点：

- **环境注入而非全局写死**：`set_env(env)` 注入 env 句柄，`PandaMotion` 懒加载；reset/换环境后重新注入即可；
- **返回值即状态**：每次工具调用都回传最新本体状态（夹爪坐标 + 成功标志），LLM 不需要记忆就能闭环决策；
- **失败显式上报**：规划无解时返回中文失败原因，而不是抛异常中断 Agent；
- `move_to` 在描述里明确标注"一般不需要单独调用"，引导 LLM 走标准两步流程。

### 3.3 标准技能序列

"把零件 X 放进盒子"= `pick(part=X)` → `place(target=box)`，SYSTEM_MESSAGE 里写死为推荐流程，实测 DeepSeek 稳定按此执行、不产生多余调用。

## 4. Agent 设计

### 4.1 运行时架构

```
用户中文指令
    │
    ▼
Qwen-Agent Assistant（agent_main.py）
    │  组装 system_message + 三个 BaseTool
    ▼
DeepSeek（云端，OpenAI 兼容 function-calling）
    │  返回 tool_calls（pick/place/move_to）
    ▼
Qwen-Agent 分发到 sim_skills 对应工具的 call()
    │
    ▼
PandaMotion → env.step(8维动作) → PhysX 物理推进
    │
    ▼
读取 TCP 位姿 / evaluate() 入盒标志 → 文本回传 LLM
    │
    └── 循环，直到 LLM 给出最终中文汇报
```

### 4.2 关键设计

1. **模型与协议**：DeepSeek 走 OpenAI 兼容接口；`llm_cfg` 必须含 `"generate_cfg": {"use_raw_api": True}`，否则 Qwen-Agent 退化为文本模板工具调用，DeepSeek 会回 DSML 文本标签而不真正执行工具。
2. **协议兼容补丁**（[agent_main.py](../agent_main.py) 的 `_patch_oai_messages()`，运行时 monkeypatch，不改安装包）：Qwen-Agent 0.0.34 给工具结果消息写的是 `id` 字段，DeepSeek 按 OpenAI 标准严格要求 `tool_call_id`，否则 HTTP 422。补丁在基类转换函数里统一改名。
3. **提示词约束**（`SYSTEM_MESSAGE`）：说明自身是固定单臂（无底盘）、场景布局、三个技能语义，并强制"以工具返回的入盒=True 作为成功唯一依据；False 绝不允许声称成功"——防止 LLM 幻觉虚报。
4. **事件循环**：Qwen-Agent 的 `agent.run()` 是流式生成器，每轮取 `responses[-1]`：`FunctionCall` 消息打印调用，`function` 角色消息打印技能返回，`assistant` 文本做思考过程展示。
5. **执行后窗口保持**：任务结束进入 `render_retry` 循环直到按 q，方便目检最终场景；hold 动作发当前关节角（见 2.6）。

### 4.3 当前边界（诚实声明）

- Agent 目前**没有用相机图像**，技能内部读取的是仿真器物体真值位姿；这是 demo 阶段的简化，视觉感知（RGB-D 颜色分割：蓝=A、黄=B）是下一阶段工作；
- 只支持桌面抓放两个物体到一个盒子，没有错误恢复重试策略（失败会如实上报，可由上层再加 ReAct 式重试）。

### 6.2 想加一个新动作 / 技能（最常见的扩展）

以"加一个 `push`（推物体）技能"为例，两处改动：

**第一步**：在 [sim_skills.py](../sim_skills.py) 仿 `Pick` 加一个 `BaseTool`：

```python
class Push(BaseTool):
    name = "push"
    description = (
        "把零件沿桌面推到指定水平位置（不夹起）。"
        "part='A' 蓝圆柱 / 'B' 黄方块，x/y 为桌面坐标。"
    )
    parameters = {
        "type": "object",
        "properties": {
            "part": {"type": "string", "enum": ["A", "B"]},
            "x": {"type": "number"},
            "y": {"type": "number"},
        },
        "required": ["part", "x", "y"],
    }

    def call(self, params, **kwargs):
        p = self._verify_json_format_args(params)
        actor, half_h = _part(p["part"])
        try:
            _motion().push_to(actor, half_h, float(p["x"]), float(p["y"]))
        except MotionPlanError as e:
            return f"push 失败（运动规划无解）：{e}。{_tcp_report()}"
        return f"push 完成。{_tcp_report()}"
```

**第三步**：在 [agent_main.py](../agent_main.py) 注册：`function_list=[MoveTo(), Pick(), Place(), Push()]`。
