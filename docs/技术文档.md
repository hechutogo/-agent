# 技术文档：PickParts XLeRobot 具身智能 Agent

> 文档对应 2026-09-20 的实际部署版本。当前有效入口是
> `src/pickparts_agent/`、`setup.sh` 和 `run.sh`；根目录旧版 Panda
> 脚本仅保留用于追溯，不属于本版本运行链路。

## 1. 当前实现结论

本项目在 ManiSkill 3 / SAPIEN 中构建 XLeRobot 轮式双臂机器人外形，
锁定底盘，由右臂完成零件 A/B 到绿色盒子的抓放。Agent 和控制层只能使用：

- 工作区相机 RGB；
- 米制深度；
- 相机内参和相机到机器人基座的标定；
- 机器人关节位置、速度。

Agent 不读取物体 `actor.pose`、接触事件、分割 ID、环境奖励、`info` 或
仿真成功标志。场景初始化必须设置物体位姿，但这些值不暴露给感知和控制层。

与早期“固定五段式”版本不同，当前 Agent 由模型按自然语言**动态组织对象级
原子动作**，支持非预设操作、连续多任务和卡点 ReAct 自恢复。

本机已经验证：

- Apple Silicon Mac 上可安装和真实渲染；
- 云端 LLM（DeepSeek）按自然语言动态拆解原子动作，而非固定五段；
- A、B 单独抓放成功，同一场景中 A 后 B 连续抓放成功；
- 遇定位丢失等卡点时，ReAct 反思可自动 retry / replace / replan 恢复；
- 窗口和无头模式都可运行；
- 当前测试为 151 项通过。

云端 LLM、VLM 经 `.env` 配置为 OpenAI 兼容端点（默认 DeepSeek），已完成
真实云端端到端验收；连续任务与卡点恢复截图见 [验收取证](evidence/)
（`flex-ab.png`、`flex-react.png`）。ASR 代码已接入，麦克风录音的硬件链路
未在本机验证。

## 2. Agent 是现成框架还是自研

### 2.1 结论

Agent 编排不再把通用 Agent 框架放在主链路，而是在 OpenAI 兼容接口之上自建
一套轻量的“四层 + 编排器”结构，全部位于 `src/pickparts_agent/`：

- **WorldState（世界状态黑板，`state.py`）**：只汇集非特权观测（RGB-D
  反投影出的物体点、bbox、置信度，以及夹爪/持物状态），供规划与反思读取；
- **Planner（规划层，`planner.py`）**：评估需求可行性，并把任务拆成扁平的
  原子动作（AtomCall）列表；
- **ReActExecutor（执行层，`executor.py`）**：顺序执行原子动作，监控每步
  成败并发出工作流/反思事件；
- **Reactor（反思层，`reactor.py`）**：动作失败时基于当前世界状态，决定
  retry / replace / replan / ask_user / abort；
- **Orchestrator（编排器，`orchestrator.py`）**：串联“可行性评估 → 规划 →
  执行/反思 → 完成追问”。

模型通过严格 JSON 交互（`llm.py` 的 `JSONChat`，`temperature=0`，原生
OpenAI 兼容 `chat.completions`，失败时一次修复重试），不依赖 Qwen-Agent。
`Endpoint.qwen_config()` 仅作为工具方法保留，默认链路不引用。

| 范围 | 来源 | 当前实现 |
|---|---|---|
| Agent 编排（规划/执行/反思） | 项目自建 | `planner.py`、`executor.py`、`reactor.py`、`orchestrator.py` |
| 严格 JSON 模型调用 | OpenAI 兼容 SDK | `llm.py` 的 `JSONChat` |
| 仿真器与物理 | 开源 ManiSkill 3 / SAPIEN | `simulation.py` |
| 机器人资产 | 开源 XLeRobot 固定 revision | `robots/assets/xlerobot/` |
| 云模型客户端 | OpenAI 兼容 SDK | `cloud.py` 的 `Endpoint` |
| 视觉定位与 RGB-D 几何 | 项目实现 | `perception.py`、`cloud.py` 的 `CloudPerception` |
| URDF FK/IK | 项目实现，SciPy 求解 | `kinematics.py` |
| 对象级原子动作 | 项目实现 | `atoms/` |
| 固定五段基线（仅 `--demo`） | 项目实现 | `motion.py` |
| CLI、语音入口、产物保存 | 项目实现 | `app.py` |

因此正确描述是：**自行搭建轻量柔性 Agent 编排与具身原子技能，复用 ManiSkill、
XLeRobot 和 OpenAI 兼容模型，不再把通用 Agent 框架放在主链路**。

### 2.2 如何使用 Agent

先配置 `.env`。LLM、VLM、ASR 都是云端 API，不下载本地模型：

```bash
cd "/Users/bytedance/Documents/具身仿真实践/pickparts-xlerobot-agent"
cp .env.example .env
```

至少填写文本交互所需的 LLM/VLM（默认 DeepSeek）：

```dotenv
LLM_API_KEY=sk-...
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-chat

VLM_API_KEY=sk-...
VLM_BASE_URL=https://api.deepseek.com
VLM_MODEL=deepseek-flash
```

文本多轮交互：

```bash
bash run.sh --view
```

可用自然语言描述单步或连续任务：

```text
把零件A放进盒子里
把A放进去之后，再把零件B也放进盒子
quit
```

成功后 Orchestrator 返回实际执行结果，并追问“还需要我做什么？”。同一进程内
`WorldState`、场景和机械臂状态持续保留，因此可以连续执行多个任务。

音频文件和麦克风入口：

```bash
bash run.sh --audio instruction.wav

uv pip install --python .venv/bin/python -e '.[microphone]'
bash run.sh --record 5
```

ASR 端点必须支持 OpenAI `/audio/transcriptions`。音频和录音模式一次只执行
一条转写后的命令；文本模式支持连续多轮。

### 2.3 无云端凭据时如何使用

固定基线演示不调用任何云端模型：

```bash
bash run.sh --demo A B --view
```

该模式使用 OpenCV 颜色定位 + `motion.py` 的固定五段动作，用于验证场景、
RGB-D、IK、物理抓取和视觉成功判定，不能作为柔性云端 Agent 已验证的证据。

其他命令：

```bash
bash run.sh --demo B
bash run.sh --demo A B --seed 0
bash run.sh --smoke
bash run.sh --help
```

### 3.2 修改 Agent 时必须保留的安全边界

1. LLM 只输出语义引用（物体 id `A`/`B`/`box` 和原子名），严禁输出坐标、
   关节角或底层控制量；坐标由原子运行时在内部接地。
2. 计划必须是扁平 AtomCall 列表，禁止嵌套循环或容器嵌套。
3. 物理成败以 `AtomResult` 为准，模型文本不能覆盖物理失败；fatal 安全错误
   立即停臂并 abort，不得重试。
4. 原子前置 `check_pre` 不满足时不执行 `run`。
5. 预算上限：反思 4 次、原子 25 次、LLM 8 次；超限安全停止并请求重置。
6. 感知模块只接收 `Frame`，不能接收环境或 actor 对象。
7. 新增成功判定只能使用视觉和本体状态，不能调用 `evaluate()` 读取真值；
   否定、歧义、越界需求在 Planner 阶段由 blockers 拦截。

### 3.3 如何新增 Agent 技能

新技能以“原子动作”方式接入，注册后 Planner/Reactor 提示词会自动获得目录：

1. 在 `atoms/library.py` 增加 `Atom` 子类，实现 `check_pre` / `run` /
   `verify`，参数只含语义目标，不含坐标；
2. 在 `atoms/registry.py` 用手写 JSON schema 声明参数；
3. 在 `atoms/__init__.py` 的 `build_default_registry()` 中注册；
4. 需要的坐标在原子 `run` 内，根据 `WorldState` 中的物体点和 IK 实时接地；
5. 增加重复调用、非法参数、前置失败、异常恢复和真实物理测试。

## 4. 当前技能库

“技能”分为对象级原子动作、感知策略和固定基线三层。

### 4.1 对象级原子动作

默认注册表（`atoms/__init__.py` 的 `build_default_registry()`）包含 9 个原子：

| 原子 | 参数 | 作用 |
|---|---|---|
| `find_object` | `target: A/B/box` | RGB-D 视觉定位，反投影 3D 点并写入 WorldState |
| `verify_state` | `target: A/B`，`at: table/box` | 视觉校验物体在桌面还是盒内 |
| `set_gripper` | `open: boolean` | 张开或闭合右臂夹爪 |
| `reach_above` | `target: A/B/box`，`clearance?` | 移动到物体上方悬停点（默认高 0.10 m） |
| `grasp` | `target: A/B` | 下降到物体并闭合夹爪 |
| `lift` | `clearance?` | 抬起并视觉确认抬高 ≥ 3.5 cm，登记持物 |
| `carry_to` | `container: box` | 把持物体搬运到容器上方 |
| `release_into` | `container: box` | 容器上方张开夹爪使其落入，再撤离 |
| `reset_arm` | — | 右臂回到 rest 姿态 |

每个原子的 `call()` 固定串起 `check_pre → run → verify`。前置负责世界状态
约束（如“尚未定位”“夹爪未张开”“正持有其他物体”），`verify` 用非特权观测
确认结果。

### 4.2 感知策略

| 策略 | 使用场景 | 输入 | 输出 |
|---|---|---|---|
| `ColorPerception` | 无 Key 的固定基线 | RGB-D、标定 | A/B/盒子的 bbox、三维点 |
| `CloudPerception` | 柔性 Agent 模式 | VLM 看 RGB；本地使用深度和标定 | bbox、置信度、三维点 |

`CloudPerception` 的数据流：

1. 只把 RGB PNG 和目标描述发送给 VLM；
2. VLM 返回原图像素坐标 bbox 和置信度；
3. 本地在 bbox 内筛选有效深度；
4. 默认按已知红/蓝/绿色做局部细化；
5. 用相机内参和 `camera_to_base` 反投影到机器人基座坐标。

VLM 不接收深度、关节状态、物体真值或三维坐标。定位 bbox 必须满足
`0≤x1<x2≤640`、`0≤y1<y2≤480`。

`WorldState` 在写入观测时推断物体位置语义 `placement`：`table` / `box` /
`gripper`（依据与盒子的水平/高度关系及持物状态），供 `verify_state` 等使用。

`verify_state` 在校验前先短暂等待释放件落定；当目标在已观测的盒内因叠放被遮挡、
无法重新定位时，沿用最近一次 `placement=box` 判定为成功，避免目标已达成却误报
失败、进而触发从盒内重抓的危险动作。

### 4.3 固定五段基线

`motion.py` 的 `PickPlace.run(target)` 仍保留“移动、抓取、抬起、放置、复位”
五段式固定链路，但只在 `--demo` 基线模式使用，不由柔性 Agent 调用。柔性
Agent 的技能来源是 4.1 的 9 个原子，顺序由 Planner 动态决定。

## 5. 一次执行的完整逻辑

### 5.1 柔性 Agent 文本模式

```text
用户自然语言
  -> Planner.analyze：结合 WorldState 判断可行性，产出扁平 AtomCall 列表
       -> 不可行：返回 blockers（缺物体/歧义/越界），请用户换说法
  -> ReActExecutor.execute：逐个执行原子
       -> Atom.call：check_pre（前置） -> run（运行时接地坐标/物理） -> verify（非特权校验）
       -> find_object：RGB 走 VLM 出 bbox，本地深度+标定反投影，写入 WorldState
       -> reach_above/grasp/lift/carry_to/release_into：URDF IK + 笛卡尔路点 + PD 关节
       -> lift 视觉确认抬高 ≥ 3.5 cm；verify_state 确认 table/box
  -> 某步失败：Reactor.decide
       -> retry：可先插入 find_object 刷新定位，再重试当前原子
       -> replace：用新原子替换当前失败原子
       -> replan：从当前位置重新规划剩余任务
       -> ask_user：网页弹窗/命令行提问，等待确认
       -> abort：fatal 安全错误强制中止停臂
  -> 全部完成：finish(success)
  -> Orchestrator 追加“还需要我做什么？”
```

关键防护：

- 非特权：模型与原子只接触 `Frame` 和 WorldState，不接触环境真值；
- 模型只给语义引用，坐标在原子内由物体点 + IK 实时接地；
- 物理失败不能被文本覆盖，fatal 强制 abort；
- 反思器自身不可用时，按错误类型安全回退（fatal → abort，其余 → replan）。

### 5.2 固定基线模式

```text
CLI 的 A/B 顺序
  -> ColorPerception
  -> motion.PickPlace 五段动作 + IK + Simulation
  -> 视觉校验和阶段证据保存
```

基线绕过的只是 LLM、VLM 和 ASR，不绕过物理仿真、RGB-D 感知或运动控制。

### 5.3 失败处理与预算

原子返回的错误类型（`AtomResult.error_kind`）：

- `lost_object`：定位丢失/目标不可见；
- `grip_failed`：抬起后视觉未确认抓起（高度变化 < 3.5 cm）；
- `unreachable`：IK 不可达；
- `verify`：TCP 跟踪或状态校验偏差（TCP 误差 > 8 mm）；
- `fatal`：物理安全错误。

处置原则：

- 定位偶发失败、TCP 近失等 transient 情况：优先 retry，并在重试前插入
  `find_object` 刷新定位；
- 重试仍失败或抓取失败：升级为 replan，从当前状态重规划剩余任务；
- fatal：立即停臂 abort，并向用户说明；
- 需要人工信息时：ask_user（网页弹窗，CLI 下直接结束并打印问题）。

执行预算（`executor.py`）：

| 预算 | 上限 | 超限行为 |
|---|---|---|
| `MAX_REACT_ITERS`（反思轮数） | 4 | 返回“反思预算耗尽”，请求重置 |
| `MAX_ATOM_CALLS`（原子调用数） | 25 | 返回“动作预算耗尽” |
| `MAX_LLM_CALLS`（模型调用数） | 8 | 返回“LLM 调用预算耗尽” |

## 6. 仿真场景如何搭建

### 6.1 机器人

机器人资产来自 `Vector-Wangel/XLeRobot`：

- 固定 revision：`a7ee564294f03484783ed053ab1550bccc3c6c09`；
- 资产目录：`src/pickparts_agent/robots/assets/xlerobot/`；
- 本地修改：把三个底盘运动关节改为 `fixed`；
- ManiSkill Agent：`PickPartsXLeRobot`；
- `fix_root_link = True`；
- 右臂执行，左臂、头部和左夹爪保持目标位置。

右臂 5 个关节：

```text
Rotation, Pitch, Elbow, Wrist_Pitch, Wrist_Roll
```

机器人具有轮式双臂外形，但当前不实现底盘导航和双臂协同。该 URDF 来自
XLeRobot 项目，不代表已独立认证其与 v0.3 实体硬件逐尺寸一致。

### 6.2 场景几何

场景在 `PickPartsEnv._load_scene()` 中用 SAPIEN ActorBuilder 创建：

| 物体 | 类型 | 尺寸/位置 |
|---|---|---|
| 桌面 | 静态 box | half-size `(0.30, 0.22, 0.025)`，顶部约 `z=0.72` |
| 桌腿 | 4 个静态 box | 支撑桌面 |
| 零件 A | 动态红色 box | half-size `(0.012, 0.012, 0.018)` |
| 零件 B | 动态蓝色 box | half-size `(0.012, 0.012, 0.018)` |
| 盒子 | 静态绿色复合体 | 底板加四面真实碰撞墙 |
| 地面 | 静态 box | 覆盖机器人和桌子区域 |

每次 reset：

- A 中心约为 `(-0.085, -0.34, 0.739)`；
- B 中心约为 `(-0.015, -0.34, 0.739)`；
- A/B 的 XY 分别加入 `[-0.008, 0.008] m` 随机扰动；
- 盒子基准位置为 `(0.085, -0.30, 0.726)`。

盒子构建 API 的 `half_size` 是半尺寸；底板和四面墙分别传入半尺寸，
避免把全尺寸误当半尺寸导致碰撞空间错误。

### 6.3 相机与观测

工作区相机：

- 名称：`workspace`；
- 分辨率：640×480；
- 位置约 `(0.45, -0.90, 1.25)`；
- 看向 `(0, -0.25, 0.75)`；
- 输出 RGB、毫米深度、相机参数。

`Simulation.observe()` 将深度转换为米，并构造：

```python
Frame(
    rgb,
    depth,
    intrinsic,
    camera_to_base,
    qpos,
    qvel,
)
```

`Frame` 类型没有成功标志、奖励、物体位姿、接触或分割字段，从接口层阻断
特权信息进入 Agent。

### 6.4 环境接口

环境使用：

```text
obs_mode="rgbd"
control_mode="pd_joint_pos"
reward_mode="none"
sim_backend="cpu"
render_backend="cpu"
```

Mac 上 ManiSkill 会使用 SAPIEN CPU backend 名称，同时渲染设备通过项目内
MoltenVK 映射到 Apple GPU/Metal，不应理解为纯 CPU 光栅化。

环境的 `_get_obs_extra()` 和 `evaluate()` 都返回空字典，避免成功真值被上层误用。

## 7. 运动学与控制

### 7.1 IK

`ArmKinematics` 直接解析项目内 URDF，不读取仿真场景：

- 从基座沿关节链计算到 `Fixed_Jaw` 的 FK；
- 使用独立 TCP 偏移 `(-0.014, -0.095, 0)`；
- 用 SciPy `least_squares` 求 5 关节位置 IK；
- 约束 TCP 位置和向下抓取接近轴；
- 对 Wrist Roll 做轻度正则；
- 位置误差小于 3 mm 且方向满足阈值才接受；
- 不可达时抛错，不执行“最近但错误”的姿态。

当前执行路径没有使用旧 Panda 版的 pinocchio CLIK，也没有使用 mplib。

### 7.2 轨迹和跟踪

- 大位移先求目标 IK；
- 已处于向下姿态时，以约 8 mm 间距生成笛卡尔路点；
- 每个关节目标用 smoothstep 插值；
- 右臂控制器为绝对关节位置 PD；
- 每段路点后读取本体 qpos，反算 TCP 检查笛卡尔误差（≤ 8 mm）；
- 左臂、头部和其他夹爪继续保持之前的目标。

夹爪驱动使用较低力矩，避免闭合时把轻量手臂结构拉垮。抓取依靠真实碰撞、
摩擦和物理推进，没有瞬移或 attach 物体。

## 8. 产物与排障

固定基线（`--demo`）每次任务生成：

柔性 Agent 模式下，CLI 在每个回合保存 `runs/turn-NNN/`（RGB + 深度/标定），
网页端则实时显示工作流与 ReAct 泳道。NPZ 保存米制深度、相机标定和 qpos，

排障顺序：

1. `bash run.sh --smoke` 检查 RGB-D；
2. `bash run.sh --demo A` 检查本地感知和物理；
3. 查看 `04-lift.png` 是否真实夹起；
4. 查看 `moves.json` 和 `result.json`；
5. 云模式先检查 `.env` 的 LLM/VLM 配置；
6. 卡点优先由 ReAct 自动恢复；预算耗尽或 fatal 后，网页点“重置”、CLI 重启
   创建新 `Simulation`，不要在异常状态上强行继续。
