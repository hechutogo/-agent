# TiPToP 初版与优化版

网页入口：`http://127.0.0.1:8765/`。执行引擎下拉框提供自研 Agent、TiPToP 初版、TiPToP 优化版。

| 行为 | 初版 `tiptop_mac` | 优化版 `tiptop_optimized` |
|---|---|---|
| 指令理解 | 最终目标谓词 | 最多 16 个有序单谓词子任务 |
| 中间状态 | 不表达跨时序目标 | 逐段验证；显式重复动作记录抓起里程碑 |
| 规划 | 一次全局 BFS | 每段读取新 RGB-D，规划一次并执行 |
| 最终状态等于起点 | 可返回空计划 | 顺序目标分别执行；要求动作时 visited key 包含过程进度 |
| 普通已满足目标 | 无动作 | 无动作 |
| 执行失败 | 立即中止 | 当前子任务有界 ReAct，默认最多 5 次尝试 |
| 成功含义 | 开环轨迹完成 | 每个子任务都通过视觉验证 |
| 日志 | 全局计划、动作 | 子任务 → 尝试 → 感知/规划/执行/验证，独立产物 |

## 示例

A 已经在盒子里时输入：

> 先把 A 放到桌面，再把 A 放回盒子。

优化版保留 `on(A, table)`、`on(A, box)` 两个目标。第一段桌面状态经观测确认后，才重新感知并规划第二段；不会把两段合并为最终 `on(A, box)`。

输入“再把 A 拿起来放回盒子”时，`require_action` 要求中间抓起状态。优化版 `_State.moved` 进入 BFS 状态键，`_satisfied` 检查该里程碑，因此起点和完成动作后回到的物理状态不会被当作同一个搜索节点。

## 恢复边界

ReAct 接收当前目标、尝试次数、失败记录和新观测摘要，只能选择重新观测、重规划或终止，不能输出坐标。轨迹仍由本地 TAMP/IK 生成。

已完成子任务不重放。失败时持物记录保留；确认仍持物则从放置继续。首次抓起需有高度变化、TCP 接近及夹爪接触证据；接触目标表面不代表已经松爪。无法确认持物状态时只重新观测；致命运动错误立即停止。持物或抓取状态不确定时禁止切换引擎，避免新引擎丢失物理状态。

规划器使用当前关节状态，按执行器相同的 8mm 笛卡尔插值逐点验证 IK。持物重规划时，验证坐标会叠加视觉测得的物体到 TCP 偏移；执行途中不可达的桌面落点会在当前子任务内按 5cm 半径排除。首次抓取前偏移尚不可观测，因此先验证名义路径，抓起后的任何恢复都改用实测偏移。

支撑检查与持物恢复共用堆叠几何规则：物块中心需在支撑边缘内至少 2mm，俯视包围盒至少一半重叠，底面与支撑顶面距离仍限定在 -3～8mm。这样允许旋转和 RGB-D 噪声带来的外框变化，盒内放置仍要求完整包含。桌面接触优先用实测底面，不将倾斜物块强行按 36mm 直立高度推算；只有盒壁遮挡时才使用已知高度补偿。

叠放后再次抓取时，规划器依次尝试 10、8、6cm 抬升候选，同时保持高于场景障碍至少 3cm，每个候选均做连续路径 IK 预检。执行器仍要求至少 3.5cm 的视觉抬升证据。

ReAct 显式接收 `grip_state=empty/holding/unknown`、最新场景、失败阶段和具体观测错误。`grip_unknown` 表示持物证据不足，不等于抓取动作失败；执行错误与后续观测错误分别保留。

当前几何适配项目中的 24×24×36 mm 物块和 6 mm 盒底。视觉遮挡或不可达情形可能在预算耗尽后停止，不保证任意随机场景成功。所有状态只来自 RGB-D 与机器人本体观测。
