# Mac XLeRobot RGB-D 部署设计与执行计划

日期：2026-09-20。用户已批准直接执行。

## 基线与目标

从 hechutogo/-agent 独立克隆，保留 Git 历史和 Qwen-Agent Assistant/BaseTool
框架。采用 XLeRobot v0.3 形态，资产以实际下载的上游 commit 固定；
不使用工作区既有 RoboTwin、StarVLA、模型或数据。
底盘锁止，右臂操作，左臂保持安全姿态。目标为 Mac 上可启动的 ManiSkill 3
仿真及 A/B 抓放；云端模型凭据缺失时仍应能运行相机、场景和确定性视觉演示。

## 架构

simulation 负责场景与机器人、动作执行；只向上层返回 RGB-D、标定、qpos/qvel。
perception 负责图像定位、反投影和视觉结果检查，不接受 actor/env。
motion 通过机器人运动学与受限执行接口控制右臂，不读取物体真值。
Qwen-Agent 接收文本，调用一个受限 pick_and_place 工具；
工具内部执行视觉观测和五段动作，模型不提交坐标或关节值。工具做状态前置检查，
失败不能声称成功；完成后程序输出“还需要什么”并接受下一条任务。
ASR 使用云端 OpenAI 兼容转写接口，支持音频文件及可选麦克风录音。
不安装本地 AI 模型。有限颜色/形状场景提供 OpenCV RGB-D 基线以便无 Key 自检，
该模式明确标识为确定性演示，不冒充云端 Agent 验证。

传感器帧只保留 RGB、米制深度、相机 K、相机到基座标定、本体关节状态。
环境 reward/info/成功标志不传给 Agent；评测读取真值只能在独立脚本中进行。
未知深度、不可见、IK 不可达、跟踪偏差均应报告失败。控制不因 API 等待失去保持。

## 验收与风险

必须实际创建 XLeRobot 场景，输出非空 RGB-D，推进物理步并保存截图。
分别验证 A/B 抓放和 A 后 B 的连续任务；不能用“推入盒”冒充抓起。
桌面、零件、盒子位置对感知层不可见；随机 seed 用于验收重现。
SO 系列每臂仅 5 个运动关节，不能照搬 Panda 7 轴固定 6D 姿态 IK；
使用位置加抓取接近轴约束及独立 TCP 标定。
上游当前 ManiSkill 代码与 v0.3 硬件版本不一定一一对应，必须记载实际 revision。
Mac 的 Vulkan/MoltenVK 能力、夹爪摩擦与可达空间需本地运行验证。
云端端到端验收必须有用户配置的多模态 API；缺凭据时准确标注未验证。
