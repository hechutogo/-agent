# 堆叠后持物状态恢复

## 症状

TiPToP 优化版完成 `A -> B` 后再次抓取 A，可能把已经成功的动作误判为
`grip_failed`，或在第二次抓取的固定悬停点发生 IK 失败。

## 根因

1. 堆叠检查要求上层物体包围盒完全落在支撑物内。RGB-D 噪声和旋转会放大轴对齐
   包围盒，导致稳定堆叠被拒绝。
2. 桌面接触判断把所有物块按已知直立高度反推底面，倾斜或遮挡观测会被误判为悬空。
3. 持物状态重建异常时丢弃了新场景，ReAct 只能基于旧状态推断失败原因。
4. 第二次抓取固定使用 10 cm 悬停高度，工作空间边缘的完整笛卡尔路径可能不可达。

## 修复

- 物块堆叠要求中心距离支撑边缘至少 2 mm、俯视包围盒重叠至少 50%，接触间隙保持
  `-3..8 mm`；盒内放置继续要求完整包含。
- 桌面接触优先使用观测底面，只在盒壁遮挡时使用已知高度补偿。
- 持物重建失败时保留最新场景，并向 ReAct 传递 `grip_state=unknown`、失败阶段和原因。
- 抓取悬停依次尝试 10、8、6 cm，且每个候选都执行 8 mm 插值的连续 IK 预检。

## 回归方法

1. 重放失败 RGB-D，分别检查堆叠、桌面接触、夹爪开度和 TCP 距离。
2. 验证 `grip_unknown` 不会被折叠为 `grip_failed`。
3. 运行 seeds 7、17、27 的 `A -> B -> box` 物理验收。
4. 运行盒内往返及注入 IK 失败恢复用例，确认已完成子任务不会重放。
